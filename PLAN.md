# Kopumi — detailed product & technical plan

## Context
Kopumi is a macOS menu bar app that hooks Cmd+C / Cmd+V across the whole system. The current scaffold has an event tap that only logs keys, a status bar icon and `run.sh` (see `Sources/Kopumi/main.swift`). The user wants a **smart clipboard manager**: on-device intelligence first, a cloud model through the user's own subscription CLI for heavy work, and **end-to-end encrypted sync with iOS/Android later**. Decisions already made:

- Core: smart clipboard manager now; cross-device sync later.
- Smart features: clip-type detection, search by meaning, context-aware paste, AI actions on paste. All four are in.
- AI: on-device first (Apple Foundation Models). Cloud = a subscription CLI the user is signed in to locally (e.g. `codex exec`, model/reasoning set in config), and only when the user picks a heavy action.
- macOS 26+ only (Apple Silicon). Foundation Models is always available.
- Cmd+V: **tap = normal paste, hold = Kopumi panel**.
- Sync: end-to-end encrypted. Design the data model for it now, build it later. Backend choice deferred.

Toolchain checked: the Command Line Tools SDK has `FoundationModels`, `NaturalLanguage`, `Vision`, `ServiceManagement` and `libsqlite3`. `codex` (at `~/.local/bin`) and `claude` are both installed. **No third-party dependencies are needed.**

---

## 1. How it works (data flow)

```
Copy happens ──► Watcher (changeCount poll 0.5s) ──► Capture
                                                     │ read pasteboard types + source app
                                                     ▼
                                               Sensitive filter ──(secret)──► store flagged / skip
                                                     ▼
                                               Classifier (instant, local rules)
                                                     ▼
                                               SQLite store (+FTS5)  ──► menu / panel update
                                                     ▼  (background, low priority)
                                               Enricher: embedding vector, on-device title
Hold Cmd+V ──► Panel (search, preview, actions) ──► Action (local / on-device AI / CLI)
                                                     ▼
                                               Paster: format for target app → pasteboard → synthetic Cmd+V
```

Rule: **capture is fast and dumb, enrichment is slow and async.** Nothing heavy runs inside the event-tap callback or on the copy path.

## 2. Features in detail

### 2.1 Capture & history
- Detect copies with `NSPasteboard.general.changeCount`, not the key tap. That catches menu copies, drag-copies and copies made by other apps.
- Save every representation that matters: `public.utf8-plain-text`, RTF/HTML, PNG/TIFF, file URLs. Plain text is the canonical form; rich formats are kept as blobs.
- Source app = `NSWorkspace.frontmostApplication` at capture time (bundle id + name). This drives context and the "ignore apps" setting.
- Duplicates: SHA-256 of the canonical content. Copying the same thing again bumps `lastUsedAt` instead of adding a new row.
- Retention: count limit + age limit. Pinned clips never expire.

### 2.2 Sensitive-content guard (required for anything smart)
- Skip a clip entirely if it has `org.nspasteboard.ConcealedType`, `TransientType` or `AutoGeneratedType` (the conventions password managers use).
- Local regexes flag likely secrets: API key prefixes (`sk-`, `ghp_`, `AKIA`, JWT shape), private key blocks, card numbers (Luhn check). Flagged clips are **not embedded, never sent to the cloud, hidden behind a blur, and auto-deleted** after N minutes.
- Ignore-list of apps (1Password, Keychain Access, ...) whose copies are never stored.

### 2.3 Clip-type detection (instant, rule-based; no LLM)
| Type | Detector | Preview / quick actions |
|---|---|---|
| URL | `NSDataDetector(.link)` | favicon + domain; open, copy clean URL (strip `utm_*`) |
| Email / phone / address / date | `NSDataDetector` | compose, call, open in Maps, add to Calendar |
| Color | regex hex / rgb() / hsl() | swatch; convert HEX↔RGB↔HSL↔SwiftUI |
| JSON / YAML | `JSONSerialization` parse | pretty-print, minify, JSON → Swift struct (AI) |
| Code | heuristics (brackets, keywords, indentation) + source app is an IDE/terminal | monospace preview, language guess |
| Table | tabs/CSV shape | grid preview; to Markdown table / CSV |
| Image | pasteboard image | thumbnail; **OCR text with `Vision`** (makes images searchable) |
| File(s) | file URLs | icons; copy path, reveal in Finder |
| Plain text | fallback | language from `NLLanguageRecognizer` |

The detector returns `kind` + extracted metadata (JSON). It's a plain function, testable with `assert`s.

### 2.4 Search by meaning
- Two-stage search, all on-device:
  1. **SQLite FTS5** on text + OCR text + title → exact/keyword hits, instant.
  2. **Semantic**: an embedding per clip from `NLContextualEmbedding` (multilingual). Cosine similarity, brute-force over stored vectors. Merge the two rankings with reciprocal rank fusion, plus a boost for recent clips.
- Filter tokens in the search box: `type:url`, `app:Xcode`, `today`, `pinned`.
- `ponytail:` brute-force vectors are fine up to about 50k clips. Add an index (sqlite-vec / IVF) only if search gets slow.
- An on-device model writes a short **title** for long clips in the background ("SQL: users joined with orders"). It shows in the list and is indexed for search.

### 2.5 Context-aware paste
- At paste time, look up the target app (frontmost bundle id) in a rules table:
  - Terminal, iTerm, Ghostty, VS Code terminal → plain text, trimmed, multi-line warning.
  - Code editors (Xcode, VS Code, Zed, JetBrains) → plain text, keep indentation.
  - Notion, Slack, Obsidian, GitHub in a browser → Markdown (rich → Markdown).
  - Pages, Mail, Notes, Word → rich text as-is.
  - Default → whatever was copied (normal behavior).
- This applies **only to pastes made through Kopumi** (panel / hold). A quick tap of Cmd+V stays 100% native, so we never surprise the user.
- The rules are a static table in code. A settings UI for editing them comes later.

### 2.6 AI actions
- Each action is **data**: `{id, title, icon, appliesTo: [kinds], engine: .onDevice | .cli, prompt template}`. They're listed in the panel next to the selected clip; actions that fit the clip's kind come first.
- On-device (Foundation Models `LanguageModelSession`, `@Generable` for structured output), quick, under 2s:
  fix grammar, make shorter, turn into a bullet list, extract (emails/dates/todos → structured), clip title, JSON → Swift struct (small inputs), rephrase in a different tone.
- Cloud CLI, heavy/slow, explicit only:
  translate long text, explain code, rewrite as a reply, summarize long documents.
  - Run `codex exec` (or any command template in Settings, e.g. `claude -p`) through `Process`. Prompt goes in on stdin, result is read from stdout. Model/reasoning come from the user's CLI config (`-c model=...`). We don't hardcode one.
  - The UI shows a progress indicator and a Cancel button (terminates the process). Timeout 120s.
  - Sensitive clips are blocked, and the first use of each action shows a "this will send the text to <CLI>" confirmation.
- Result: preview in the panel → Enter pastes it (and saves it to history as a new clip with `derivedFrom`).
- Custom actions (the user writes their own prompt) come later.

### 2.7 Hold-Cmd+V panel (main UI)
- Key-tap state machine (inside the existing callback in `main.swift`):
  - Cmd+V keyDown (no other modifiers, not our synthetic event) → **swallow**, note the time, start a 300 ms timer.
  - keyUp before the timer fires → post a synthetic Cmd+V tagged with `eventSourceUserData = 'KOPU'` → native paste.
  - Timer fires while the key is still held → show the panel. Swallow the auto-repeat keyDowns.
  - Our own tagged events are always passed through untouched.
  - Re-enable the tap on `tapDisabledByTimeout` / `ByUserInput` (missing today).
- Panel: an `NSPanel` (`.nonactivatingPanel`, floating) holding a SwiftUI view, shown at the text cursor (AX `kAXBoundsForRangeParameterizedAttribute`, falls back to the mouse position).
  - Left: search field + clip list (type icon, title/preview, source app, time). Right: preview + actions.
  - Keys: type to search, ↑↓ to move, Enter = paste (context-aware), ⌥Enter = paste as plain text, Cmd+1…9 = quick paste, Tab = focus the actions list, Esc = close.
- Double Cmd+C (within 400 ms) → add the new selection to the end of the previous clip (separated by a newline).

### 2.8 Menu bar
- Last 10 clips, Pause capture (for 1h / until resumed), Clear history, Settings, Quit. The icon shows when capture is paused.

### 2.9 Settings (SwiftUI `Settings` scene)
History limits, hold delay, apps to ignore, sensitive auto-delete time, AI CLI command template + test button, start at login (`SMAppService.mainApp`), first-run screen explaining the Accessibility permission.

## 3. Data model (SQLite, ready for sync)
```
clips(
  id TEXT PK (UUIDv7),      -- globally unique → sync-safe
  createdAt, updatedAt, lastUsedAt INTEGER (ms),
  deviceId TEXT,            -- origin device
  kind TEXT, sourceApp TEXT,
  text TEXT, title TEXT, meta JSON,
  contentHash TEXT UNIQUE,
  pinned INT, sensitive INT, expiresAt INTEGER NULL,
  derivedFrom TEXT NULL,
  deleted INT DEFAULT 0     -- tombstone, so deletions sync
)
blobs(clipId, uti TEXT, data BLOB)          -- rich/image representations
embeddings(clipId PK, model TEXT, vec BLOB) -- local-only, never synced (recompute per device)
clips_fts USING fts5(text, title, ocr, content=clips)
```
- Plain SQLite3 C API through a thin wrapper (~100 lines). No ORM, no SwiftData (its macros are a risk without Xcode).
- File: `~/Library/Application Support/Kopumi/kopumi.sqlite`. Encrypting the database at rest is deferred; it relies on FileVault until sync work starts.

## 4. Code layout (SwiftPM stays; switch to Xcode only when signing/notarizing needs it)
```
Sources/Kopumi/
  main.swift          app entry, status item, wiring
  KeyTap.swift        event tap + Cmd+V hold / double Cmd+C state machine
  Watcher.swift       pasteboard polling + capture
  Store.swift         SQLite wrapper, schema, queries, FTS
  Classifier.swift    type detection + sensitive guard (pure functions)
  Search.swift        FTS + embeddings + rank merge
  Paster.swift        context rules + write pasteboard + synthetic Cmd+V
  AI.swift            action list, FoundationModels engine, CLI engine
  Panel.swift         NSPanel + SwiftUI views
  Settings.swift
```
The step at the end of `run.sh` that adds files stays the same. Add `-Xswiftc` / linker flags only if they're needed for sqlite (`linkerSettings: [.linkedLibrary("sqlite3")]`).

## 5. Build order (each milestone ends usable)
1. **M1 – History core**: Watcher, Store, Classifier (types + sensitive), menu shows the last 10, click to paste (Paster with synthetic Cmd+V), tap re-enable fix.
2. **M2 – Panel**: Cmd+V hold state machine, NSPanel UI, FTS search, keyboard navigation, previews, context-aware paste.
3. **M3 – Intelligence**: embeddings + semantic search, on-device titles, OCR for images, on-device AI actions.
4. **M4 – Cloud actions**: CLI engine, confirmation, progress/cancel, settings for the command template.
5. **M5 – Polish**: Settings window, start at login, onboarding, double Cmd+C, pause, icons.
6. **M6 – Ship**: Developer ID signing + notarization (Accessibility permission stops resetting), DMG.
7. **Later – Sync (iOS/Android)**: design decision then (own relay vs. CloudKit + separate Android transport). It must be E2E encrypted (per-account key, devices paired by QR, server sees only ciphertext). The schema above already supports it (UUIDs, deviceId, updatedAt, tombstones).

## 6. Risks / open points
- **Secure input** (password fields) blocks the tap → Kopumi does nothing there. That's acceptable.
- **Swallowing Cmd+V** must never lose a paste. The state machine needs `assert` self-checks for every keyDown/keyUp/modifier-release order.
- **Hold detection vs. key repeat**: macOS repeat starts around 250–500 ms, so the hold delay is a setting (default 300 ms).
- **Apps that read Cmd+V themselves** (games, VMs, remote desktop) → add them to a pass-through list.
- **CLI latency/cost** (high reasoning can take 10–60 s) → always explicit, always cancellable.
- **Foundation Models context window** is small → long inputs go to the CLI engine automatically.

## 7. Verification
- `swift build` clean, `./run.sh` launches with the menu bar icon.
- Self-check target (`swift run KopumiChecks` or `assert`s in `#if DEBUG`) covering: classifier on sample strings (URL, hex color, JSON, AWS key → sensitive), the key state machine with scripted event sequences, Store insert/dedupe/FTS query.
- Manual end to end per milestone: copy in Safari/Xcode/Terminal → appears in the menu with the right type; quick Cmd+V pastes natively in TextEdit; holding Cmd+V opens the panel; Enter in Terminal pastes plain text; a "fix grammar" action works offline (Wi-Fi off); copying a fake `sk-...` key is blurred and expires.
