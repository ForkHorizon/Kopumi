# Kopumi sync protocol v1

Every device (Mac, Android) talks only to the **relay**: an HTTPS + WebSocket mailbox that stores encrypted records. Devices never need to reach each other, so any mix of networks works (Wi-Fi, mobile data, different NATs), and a device that was offline catches up when it comes back.

## Keys
- `accountKey`: 32 random bytes, created by the first device. Moves to new devices only inside the pairing link (QR code), never over the network.
- `encKey   = HKDF-SHA256(ikm: accountKey, salt: empty, info: "kopumi-enc-v1",  32 bytes)`
- `authToken = hex(HKDF-SHA256(ikm: accountKey, salt: empty, info: "kopumi-auth-v1", 32 bytes))`
- `accountId`: random lowercase UUID.

The relay sees `accountId`, `sha256(authToken)` and ciphertext. It can't derive either key.

## Pairing link
```
kopumi://pair?r=<relay base URL, percent-encoded>&a=<accountId>&k=<base64url(accountKey), no padding>
```
Shown as a QR code (and copyable text). Any paired device can show it.

## Record
Plaintext = UTF-8 JSON of one clip (field order doesn't matter, unknown fields are ignored):
```json
{"v":1,"id":"<uuidv7>","createdAt":0,"updatedAt":0,"lastUsedAt":0,"deviceId":"<uuidv7>",
 "kind":"text","sourceApp":null,"text":"…","title":null,"meta":null,"contentHash":"text:<sha256 hex>",
 "pinned":false,"derivedFrom":null,"deleted":false}
```
- Times are Unix milliseconds. `meta` is a JSON-object string (as stored) or null.
- `contentHash` = `<prefix>:` + lowercase hex SHA-256 of the raw UTF-8 bytes, no normalization. Prefixes: `text`, `files`, `image`. Tombstones: `deleted:<id>`.
- Tombstone (`deleted: true`): `text`, `title`, `meta` are null.
- Never sent: sensitive clips, embeddings, OCR text, blobs (images/rich text — phase 2).

Sealed record = base64( nonce(12) ‖ AES-256-GCM ciphertext ‖ tag(16) ), key `encKey`, AAD = UTF-8 bytes of the clip `id` (the relay can't move a record to another id).

## Order (last writer wins)
A version is `(updatedAt, deviceId)`, compared lexicographically. The relay and every device keep only the greater version of each id. The envelope carries `ts` (= updatedAt) and `dev` (= deviceId) in the clear so the relay can enforce this. ponytail: this leaks edit times to the relay; ids are UUIDv7 and leak creation time anyway.

**Same content on two devices** (`contentHash` is unique per device): when a live remote clip has the same `contentHash` as a different live local clip, the clip with the **smaller id** stays; the other one is tombstoned with `updatedAt = max(now, its updatedAt + 1)` and pushed. Both devices reach the same result.

## HTTP API
All requests carry `Authorization: Bearer <authToken>`. The first request to an unknown `accountId` claims it (stores `sha256(authToken)`); later requests with a different token get `401`.

| Method | Path | Body / query | Response |
|---|---|---|---|
| POST | `/v1/a/<accountId>/records` | `{"records":[{"id","ts","dev","data"}]}` (≤ 500) | `{"seq":N,"accepted":k}` |
| GET | `/v1/a/<accountId>/records?since=S&limit=L` | L ≤ 500 | `{"records":[{"seq","id","ts","dev","data"}],"seq":maxReturnedOrS,"more":bool}` |
| GET | `/v1/a/<accountId>/ws` | WebSocket upgrade | server sends `{"seq":N}` after every accepted push |
| DELETE | `/v1/a/<accountId>` | — | `204`; wipes the account (used by "unpair all"). Every later request gets `410`, so unpaired devices can tell |

Limits: `data` ≤ 400 000 chars, 50 MB per account (`413`). Every accepted write gets a new `seq`, so `since=` returns each id at most once, at its latest version.

## Client loop
1. Pull `since=<cursor>` until `more=false`; apply each record (decrypt, last-writer-wins, collision rule); save cursor.
2. Push local changes (dirty, non-sensitive) in batches of ≤ 200; clear dirty for rows that didn't change meanwhile.
3. Keep the WebSocket open while the app is in use; on `{"seq":N}` with N > cursor, run the loop. Also run on launch, on local change (debounced 1 s), and periodically.

Test vectors for hashes, crypto and the classifier are in `vectors/`, generated by `gen-vectors.mjs` (Node, no deps). Mac (`Kopumi --check`) and Android (unit tests) both verify against them.
